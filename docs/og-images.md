# OG 이미지 생성 [확정, 가은 11/04]

> 링크 미리보기(OG) 이미지 3장을 만드는 AI 작업 기준. 이 문서를 읽은 AI는 이미지 생성, 문구 배치, 렌더까지 직접 한다.
> 원본: Figma 「국립공원공단 반달이 UI」 OG 페이지(node 815:47189). 아래 수치는 그 세 프레임에서 옮겼다.

## 만드는 이미지

| 파일 | 크기 | 쓰는 곳 | Figma 프레임 |
|---|---|---|---|
| `og-facebook-1200x630.png` | 1200×630 | `og:image` 기본(페이스북·대부분의 메신저) | 844:24776 |
| `og-x-1200x675.png` | 1200×675 | `twitter:image` | 844:24790 |
| `og-kakao-800x400.png` | 800×400 | 카카오톡 공유 | 844:24803 |

## 구성 (모든 크기 공통)

**큰 틀 [가은 11/04]:** 프레임을 가로로 반씩(1:1) 나눈다. 왼쪽 반은 문구, 오른쪽 반은 캐릭터. 입력창은 가운데 선에서 시작해 캐릭터 몸 위에 겹친다. 아래 수치에 없는 새 크기도 이 틀로 잡는다.

뒤에서 앞 순서.

1. **바탕색** `color.bg` (반달이 #f5f4f0)
2. **배경 그림**: 연한 풍경. 50% 투명도로 깐다.
3. **캐릭터**: 투명 배경, 인사하는 전신. 오른쪽에 크게 두고 다리는 프레임 아래로 잘린다.
4. **문구 묶음**(왼쪽, 세로 가운데): 뱃지 → 워드마크 → 부제 2줄 → 기관 로고
5. **질문 입력창 + 보내기 버튼**: 캐릭터 몸 위에 겹친다. 반달이 앱의 입력창 컴포넌트(V6/Base/Conversation/Input, ActionSlot)를 키운 것. 입력창은 흰색 80% 반투명에 **배경 흐림(backdrop blur)** 을 넣어 뒤의 캐릭터가 뿌옇게 비친다.

## 입력

사용자에게 받을 것. 빠진 것만 묻는다.

| config 키 | 내용 | 반달이 예 |
|---|---|---|
| `badge` | 뱃지 문구, 공백 포함 13자 이하 | AI 국립공원 탐방 안내 |
| `name` | 캐릭터 이름(워드마크의 대체 글) | 반달이 |
| `wordmark` | 캐릭터 이름 로고(SVG 권장, 410:160 비율 안에) | example/wordmark.svg |
| `headline` | 부제 2줄, 줄마다 공백 포함 13자 이하 | 탐방 코스부터 준비물까지, / 반달이에게 물어보세요. |
| `question` | 입력창 예시 질문, 공백 포함 17자 이하 | 가족과 걷기 좋은 코스 추천해줘 |
| `orgLogo`, `orgName` | 기관 로고(가로형, SVG 권장)와 이름 | example/org-logo.svg, 국립공원 |
| `character` | 캐릭터 그림 | 아래 「이미지 생성」 |
| `background` | 배경 그림 | 아래 「이미지 생성」 |
| `color` | `bg` 바탕, `brand` 뱃지·입력창 선·보내기, `ink` 부제, `badgeText`, `inputText` | #f5f4f0, #125c56, #142729, #f1f1f2, #11151c |

- 색은 프로젝트 팔레트에서 고른다(제안): `brand` = main-700, `ink` = main-900, `bg` = gray-50. `badgeText`·`inputText`는 그대로 둔다. 대비 4.5:1을 확인한다.
- 워드마크와 기관 로고는 AI가 만들지 않는다. 없으면 사용자에게 받는다.
- 글자 수는 기준일 뿐이고, 실제 판정은 렌더할 때의 넘침 검사가 한다.

## 이미지 생성

### 캐릭터

[캐릭터 이미지 생성](character-images.md)에서 만든 `{이름}-hello.png`(인사하는 전신, 투명 배경)를 그대로 쓴다. 없으면 그 문서의 순서대로 먼저 만든다.

- 투명 여백을 잘라서 넣는다. 템플릿은 잘라낸 그림의 왼쪽·위·높이로 자리를 잡는다.
- 한 손을 든 쪽이 문구 쪽(왼쪽)을 향하면 좋다. 반대면 좌우 반전을 사용자에게 묻는다.

### 배경

참조: [og/example/background.jpg](og/example/background.jpg). 이미지 생성 도구에 이 그림을 참조로 함께 넣는다.

```
링크 미리보기 이미지의 배경 그림을 만들어 줘. 참조 그림(background.jpg)과 같은 구도·밝기·화풍으로.
가로 1729×910(약 1.9:1). 단순한 평면 일러스트, 파스텔.
위쪽 2/3는 거의 흰 하늘로 비워 둠(글자와 캐릭터가 올라감).
아래쪽 1/3에 {지역 소재, 예: 낮은 산 능선과 들판}이 아주 연하게 겹쳐 있고,
오른쪽 아래 구석에만 {지역 상징, 예: 나무 몇 그루와 굽은 오솔길}을 조금 진하게.
색은 {대표 색, 예: 연두·초록} 계열 연한 톤. 사람·동물·글자·로고 넣지 않기.
```

- 템플릿이 50% 투명도로 깔기 때문에 원본은 참조처럼 조금 진해도 된다.
- 왼쪽 아래(기관 로고 자리)와 가운데(입력창 자리)에 진한 요소가 오면 다시 만든다.

## 작업 순서

1. **입력 확인**: 위 표에서 빠진 것만 묻는다.
2. **이미지**: 캐릭터를 준비하고 배경을 만든다. 배경은 사용자에게 보여 주고 확정받는다.
3. **config 작성**: [og/example/bandali.json](og/example/bandali.json)을 복사해 값을 채운다. 경로는 `docs/og` 기준이다.
4. **렌더**: `node docs/og/render.mjs <config.json> <저장 폴더>`. Playwright와 Chromium(또는 설치된 Chrome)이 필요하다. WebKit은 입력창 배경 흐림을 그리지 않아서 쓰지 않는다. 문구가 넘치면 저장하지 않고 어느 칸(badge, headline, question)인지 알려 준다. 그 문구를 줄여 다시 렌더한다. 뜻을 바꾸는 줄임은 사용자에게 묻는다.
5. **검수**: 세 장을 열어 확인한다.
   - 캐릭터 얼굴이 입력창·문구에 가리지 않는다.
   - 입력창이 캐릭터 몸 위에 있고 프레임 밖으로 나가지 않는다.
   - 입력창 뒤 캐릭터가 또렷하지 않고 뿌옇게 비친다(배경 흐림이 빠지면 선이 또렷하다).
   - 배경의 진한 부분이 글자 뒤에 오지 않는다.
   - 카카오(800×400)에서도 부제 2줄과 로고가 다 보인다.
6. **넘기기**: PNG 세 장과 config를 전달한다. 페이지 `<head>`에 넣을 태그도 함께 적는다.

```html
<meta property="og:image" content="{주소}/og-facebook-1200x630.png">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:image" content="{주소}/og-x-1200x675.png">
<!-- 파비콘은 아바타 프로필 이미지(캐릭터 이미지 문서의 「파비콘」) -->
<link rel="icon" type="image/png" sizes="32x32" href="{주소}/favicon-32.png">
<link rel="apple-touch-icon" href="{주소}/apple-touch-icon.png">
```

카카오 공유 이미지(800×400)는 카카오 SDK의 `imageUrl`에 넣는다.

## Figma에 반영할 때

Figma 원본을 갱신해야 하면, Figma 연결이 있는 AI가 OG 페이지의 세 프레임에서 아래만 바꾼다. 레이어 구조와 수치는 건드리지 않는다.

| 바꿀 것 | 레이어 |
|---|---|
| 배경 그림 | `image 3`(x는 `image 2`)의 이미지 채우기 |
| 캐릭터 | `image 4`의 이미지 채우기 |
| 뱃지·부제 | `Frame 3` 안 텍스트, `Frame 2147239250`(카카오는 `…251`) 안 텍스트 |
| 워드마크·로고 | `Wordmark`, `Group 5` |
| 질문 | `V6/Base/Conversation/Input` 인스턴스의 텍스트 |

숨김 레이어(`Rectangle 1`, `Rectangle 2`)와 프레임 밖의 `Group 1`(그림자 타원), 숨김 프레임 `2472E0505940EFEA04 1`은 쓰지 않는다.

## 금지

- 템플릿 수치를 프로젝트마다 바꾸지 않는다. 바꿀 필요가 있으면 사용자에게 먼저 묻는다.
- 문구를 넘치게 둔 채 글자 크기를 줄여 맞추지 않는다. 문구를 줄인다.
- 입력창의 배경 흐림을 빼거나, 그림자를 입력창 묶음 전체에 `filter`로 걸지 않는다. 묶음에 filter가 걸리면 흐림이 뒤를 보지 못해 빠진다.
- 기관 로고·워드마크를 AI가 다시 그리거나 비슷하게 만들지 않는다.
